# 墙体结构执行计划 V1

## 目标

先完成一套可控、可手工编辑、能够严丝合缝围成封闭空间的工业监狱墙体组件。美术风格由项目负责人验收；在风格验收通过前，只锁定几何规则，不锁定材质细节。

## 不变的结构合同

- 网格单元：`48×48 px`。
- 视觉墙宽：`32 px`，横向与竖向完全一致。
- 墙体由“上沿高光/金属压边 + 墙身主体 + 底部接触阴影”组成，不能只剩一条线。
- 结构组件必须覆盖：横向、竖向、四角、T 口、十字、端帽、门框。
- 相邻组件的接口必须在网格边界上连续；不允许透明缝、黑缝或墙宽突变。
- 墙体层只负责墙和门框；地板、装饰、光源分别放在独立层或节点中。
- 地图不再使用“矩形自动补四面墙”的运行时方案；地图构图以可在 Godot 编辑器中直接修改的 `TileMapLayer` 单元为准。

## Agent 分工

### 1. 结构审计 Agent

只检查几何规则、连接掩码、封闭性和墙宽，不改美术素材。输出断点坐标、缺失组件和最小修复建议。

### 2. 素材管线 Agent

只负责把经过风格验收的原始材质整理成 48px 网格素材，并保持像素边界、透明度和原始美术观感；不直接修改地图布局。

### 3. Godot TileSet Agent

负责 `TileSetAtlasSource`、墙体碰撞、光遮挡、TileMapLayer 分层和编辑器可用性；不得通过运行时脚本覆盖手工编辑结果。

### 4. 地图搭建 Agent

使用规范化墙体组件绘制 `cell_block_a2`，先铺地板，再逐格放置墙体、门框和装饰，保证每个房间有明确的封闭外框和可识别的通道。

### 5. QA Agent

运行无头 Godot 导入、TileSet 构建、像素连接审计、封闭空间审计和运行时截图检查；发现错误直接给出文件与坐标，不把中间排错转交给用户。

## 阶段与验收门槛

### 阶段 A：几何样板

完成一个独立闭合矩形、一个带门洞矩形、一个 T 口和一个十字连接样板。验收只看：墙宽一致、连接无缝、墙身有立体截面。

### 阶段 B：TileSet 可编辑性

在 Godot 编辑器中可按 48px 网格选择每个组件；墙体、地板、门框、装饰分层；碰撞和遮挡与墙身一致。

### 阶段 C：cell_block_a2

完成外框、房间、走廊和门框。外框必须覆盖整个地图网格，不允许因为 `Rect2i` 尺寸/坐标误用而少一列或少一行。

### 阶段 D：运行时验证

验证角色不会被装饰遮挡、墙体不会出现悬空短块、光源不会穿墙、地图可读且可行走。

### 阶段 E：美术风格验收

由用户评估材质、色调、立体感和整体一致性。用户未通过时，只回退素材层，不破坏已经通过的几何和 TileSet 结构。
